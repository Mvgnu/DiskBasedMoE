# Recovery milestone: independent review and execution record

Date: 2026-10-23. Original repository baseline: `d345650`. This record distinguishes
builder checks, independent artifact review and unmeasured hardware outcomes.
Revision IDs below identify local review milestones; publication consolidates
the reviewed changes into the pull request's final source tree.

## Process and ownership

The PM froze system/domain specifications and a shared generation protocol before
builders edited code. Runtime and service builders used separate branches/worktrees
and disjoint paths. Evaluation was built by the PM and independently criticized.
Fresh critics received goal, external bar, specifications and executable artifact;
they received no builder report/conversation and edited no source. Their scope
included source inspection but required actual execution.

## Runtime — scoped pass after a native-output defect

The fresh critic compared native versus disk outputs across FP32/BF16/FP16, two
sequences, cached steps and seven cache budgets, and tested checkpoint export,
corruption, eviction, request isolation and cancellation. Most comparisons were
bit-for-bit. It nevertheless rejected in-memory export parity for a wider BF16
model: `.to(bfloat16)` rounded a nonpersistent rotary frequency, while reload
reconstructed FP32 frequencies. A concrete prefix produced native EOS token 31
but disk token 29. Canonical checkpoint-loaded native inference still matched.

At `7b31b66`, the critic reran the identical reproducer and observed native EOS 31
and disk EOS 31, with maximum logit error 0.0. The in-memory export now preserves
the actual static rotary buffer values/dtypes. A separate checkpoint export
preserves the constructor's FP32 rotary state and matches native `from_pretrained`.
The two source contracts remain distinct rather than silently normalizing them.

Independent follow-up covered FP32/BF16/FP16, eager/SDPA, two 33-token prompts,
five cached steps, exact native routes/weights, and zero/24,600-byte cache budgets.
Every executed combination was bit-for-bit equal; peak retained bytes under the
nonzero budget were 24,576. Linear, YaRN, Llama3 and proportional static RoPE were
also exercised. Changed frequency/scaling/sequence state, dynamic/LongRoPE,
missing buffers, corrupt payloads and incompatible snapshots were rejected.
Artifacts without a snapshot require re-export. The critic argued for a scoped
CPU runtime pass; no numerical tolerance was relaxed.

### Real-checkpoint layout follow-up — scoped pass

The PM inspected the official GLM-4.7-Flash configuration and tensor index at
`7dd20894a642a0aa287e9827cb1a1f7f91386b67`, without downloading weight payloads.
Its auxiliary prediction layer is unused by the pinned native decoder, but the
initial strict exporter would reject it only after exporting the live decoder.
The builder added complete name preflight and a narrow, explicitly recorded
exception for the declared complete auxiliary layout.

At `5b4a1f2`, the critic independently executed the metadata preflight: 9,703
source names, 9,491 consumed decoder names and exactly 212 excluded auxiliary
names. It then exported small 47-layer native fixtures in packed/separate and
sharded/unsharded layouts. All four matched native greedy output through cached
steps; maximum FP32 logit error was below 8e-8, within the declared
`rtol=1e-5, atol=1e-6`. Native routing indices matched exactly. Guarded tensor
reads and shard opens proved auxiliary tensors and auxiliary-only shards were
not accessed. Shared source shards can still contain unused bytes.

Missing/unknown names, partial/mixed expert layouts, incomplete or undeclared
auxiliary state, live layer 47 and unsafe paths were rejected before tensor
get/shape calls. Mocked Hub transport exercised the actual exporter, verified
resolved-revision propagation and live-shard-only requests, and proved invalid
or unindexed remote sources fail after metadata calls. Remote unsharded sources
now require a local download first; live network/authentication was not reviewed.

The touched expert calculation was independently compared against native eager
experts over 129 token rows in FP32/BF16/FP16: exact output equality. The earlier
BF16/EOS and canonical-checkpoint cached regressions remained bit-for-bit equal.
The critic argued for a scoped pass. This verifies the official metadata and
small executed fixtures, not a full-size GLM checkpoint run.

## Onboarding and browser smoothing — scoped pass after one correction

A fresh critic built the wheel, installed it outside the checkout and followed
the README through FP32 tiny export, benchmarking, localhost serving and planning.
It also installed only the base wheel in a fresh environment with no ML packages;
the three documented planning commands succeeded there.

The original tiny-server command inherited a 128-token output default, equal to
the fixture's entire context window. The UI's first nonempty message therefore

resolved that first-run blocker. The critic independently restarted with the
revised command and verified the server-advertised default and successful JSON/SSE.

The critic then rebuilt the current `7b31b66` wheel, exported a fresh fixture, and
drove the actual packaged UI in Chrome Headless Shell 151.0.7922.34. Desktop
1440 x 1000 and mobile 390 x 844 passed first message, SSE completion, New
conversation, Stop and a subsequent request. Screenshots were visually inspected;
there was no horizontal overflow, uncaught page error or remote asset request.
The installed wheel SHA-256 was
`b0073ed7026c0f35636e82ff0ca09654e2646de814ff8e697bcc1dc79e4dfaf4`.

The first browser install returned HTML from the Playwright CDN instead of a ZIP.
The critic investigated and obtained the same pinned browser archive from its
official Google storage origin. Browser absence was therefore a resolved setup
problem, not a permanent untested exception. Mobile means Chromium emulation,
not a physical phone/Safari; accessibility and broad browser compatibility were
not reviewed. Fixture output quality and incidental timings establish no
pretrained-model or large-model performance result.
